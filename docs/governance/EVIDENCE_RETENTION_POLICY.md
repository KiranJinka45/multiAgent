# Failure Evidence Archive & Retention Policy

## Purpose
To ensure long-term forensic accountability and legal reproducibility, this document explicitly defines the retention windows and handling procedures for failure evidence generated by the ZTAN platform.

## 1. Forensic Export Rules
All forensic exports from the `FORENSIC_EXPORT` API endpoints must be:
* **Format:** Canonicalized JSON, UTF-8 normalized.
* **Structure:** Append-only and strictly sequence-ordered by PostgreSQL WAL ID.
* **Immutability:** Hashable and reproducible across completely disconnected environments.

## 2. Retention Windows
| Data Class | Minimum Retention | Storage Medium |
| :--- | :--- | :--- |
| **Operator Audit Logs (Quorum actions)** | 7 Years | Immutable WORM (Write Once Read Many) Ledger |
| **Quarantine Evidence (State dumps)** | 3 Years | Cold Storage / S3 Glacier |
| **WAL Evidence Preservation (Replay logs)** | 1 Year | Compressed Parquet / Cold Storage |
| **Routine Telemetry** | 30 Days | Rolling PostgreSQL Partitions |

## 3. Operator Audit Retention
Every operator action resulting in a state transition (e.g., `QUARANTINED` $\rightarrow$ `REBUILDING`) is permanently bound to the operator's cryptographic identity (WebAuthn Attestation Hash). These records are excluded from routine GDPR/CCPA deletion paths due to overarching regulatory and security compliance mandates.
