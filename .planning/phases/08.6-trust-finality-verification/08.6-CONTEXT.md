# Phase 08.6 Context: Trust Finality Verification

## Operational Intent
Following the completion of the basic data structures and simulator drills in Phases 08.4 and 08.5, an independent audit highlighted a critical gap: the `TrustRegistry` and `OfflineAuditor` relied on structural mock checks (string matching) rather than empirical cryptographic validation.

To consider the Trust Finality subsystem genuinely validated and ready for production trust decisions, ZTAN must empirically prove trust chain portability and key revocation using real cryptography.

## Core Objectives

### 1. Empirical Cryptographic Implementation
- Transition the `ztan-auditor` offline CLI from mock string checks to real Ed25519 signature verification.
- Update the `TrustRegistry` to anchor public keys in addition to Merkle roots, supporting cryptographic revocation.
- Provide a utility to generate a real `EvidencePacket` and sign it with dynamically generated Ed25519 keypairs.

### 2. End-to-End Cryptographic Trust Validation
Demonstrate a complete validation loop:
1. Generate an `EvidencePacket` and sign it with actual keys.
2. Export a `TrustRegistry` snapshot containing the valid keys and epoch.
3. Verify the packet offline using `ztan-auditor`.
4. Revoke one of the signing keys.
5. Re-run verification to ensure rejection occurs for cryptographic reasons.

## Success Metric
The audit verifies that cross-cell interoperability, cryptographic trust portability, real revocation validation, and operational resurrection can be performed using standard cryptographic primitives (Node `crypto`) and verified on real signatures.
