# Phase 8, Plan 1: Trust-Path & Core Package Explicit `any` Elimination

## Objective

Eliminate explicit `any` type annotations from the three trust-path cryptographic packages (`ztan-crypto`, `governance-core`, `ztan-auditor`) and from the highest-impact core packages (`ztan-witness`, `core-engine`, `contracts`). These packages form the critical cryptographic and governance boundary of the platform. Replacing `any` with concrete types in these modules materially improves the ability of TypeScript to catch runtime errors at compile time.

## Scope Boundary

This plan targets **trust-path packages only** (185 `any` findings across 54 files) plus the highest-density core modules. The broader monorepo debt (3,100+ remaining findings in `utils`, `root`, `apps/*`, `deploy/*`) is explicitly **out of scope** for this plan but is tracked for future reduction.

## Strategy

The `any` usages fall into five recurring patterns across the codebase:

1. **Interface index signatures**: `[key: string]: any` → Replace with `Record<string, unknown>` or specific union types
2. **Catch clause variables**: `catch (e: any)` → Replace with `catch (e: unknown)` and add type narrowing guards
3. **Function parameter/return types**: Untyped callback params, event handlers → Add concrete signatures
4. **`Record<string, any>` metadata bags**: → Replace with `Record<string, unknown>` or typed interfaces
5. **Type assertion escape hatches**: `as any` casts → Replace with proper generics or intermediate types
