# Phase 3 Plan: Infrastructure Certification

This plan certifies the clean-sheet infrastructure deployment and smoke testing of the ZTAN services in Docker Desktop Kubernetes.

## Objectives

- Verify and hardening individual Docker image builds for `auth-service`, `gateway`, and `worker`.
- Deploy raw Kubernetes manifests to local Docker Desktop Kubernetes and monitor service health.
- Run external smoke-test campaigns against the deployed cluster services via ingress.
- Generate complete deployment and rollback evidence in `INFRASTRUCTURE_CERTIFICATION.md`.

## Tasks

<task id="OPS-INFRA-DOCKER-BUILD">
  <read_first>
    - deploy/auth-service/Dockerfile
    - deploy/gateway/Dockerfile
    - deploy/worker/Dockerfile
  </read_first>
  <action>
    Run docker builds locally to ensure no dependency compilation or resolution issues:
    1. Build auth service: `docker build -t ghcr.io/kiran/multiagent-auth:v1.1.0 -f deploy/auth-service/Dockerfile .`
    2. Build gateway service: `docker build -t ghcr.io/kiran/multiagent-gateway:v1.1.0 -f deploy/gateway/Dockerfile .`
    3. Build worker service: `docker build -t ghcr.io/kiran/multiagent-worker:v1.1.0 -f deploy/worker/Dockerfile .`
    Remediate any bundler config mismatch or missing packages.
  </action>
  <acceptance_criteria>
    - All three builds complete successfully (exit code 0).
    - Running `docker images` lists the v1.1.0 tags for multiagent-auth, multiagent-gateway, and multiagent-worker.
  </acceptance_criteria>
</task>

<task id="OPS-INFRA-K8S-DEPLOY">
  <read_first>
    - k8s/auth-deployment.yaml
    - k8s/gateway-deployment.yaml
    - k8s/worker-deployment.yaml
    - k8s/secrets.yaml
  </read_first>
  <action>
    Switch context to Docker Desktop Kubernetes and deploy the raw manifests:
    1. Select context: `kubectl config use-context docker-desktop`
    2. Apply secret declarations: `kubectl apply -f k8s/secrets.yaml`
    3. Apply core deployments: `kubectl apply -f k8s/auth-deployment.yaml`, `kubectl apply -f k8s/gateway-deployment.yaml`, `kubectl apply -f k8s/worker-deployment.yaml`
    4. Wait for deployment readiness: `kubectl rollout status deployment/auth-deployment` (or matching deployment name in manifests)
  </action>
  <acceptance_criteria>
    - Running `kubectl get deployments` shows all core service deployments are active and fully ready (1/1 or matching configured replicas).
  </acceptance_criteria>
</task>

<task id="OPS-INFRA-SMOKE-TEST">
  <read_first>
    - scripts/run-smoke-tests.js
    - k8s/ingress.yaml
  </read_first>
  <action>
    Configure and run external smoke-test validations against ingress:
    1. Deploy ingress manifests: `kubectl apply -f k8s/ingress.yaml`
    2. Perform external query validation to check routing:
       - Gateway health check: `curl -i http://localhost:3020/health` (or mapped port)
       - Auth health check: `curl -i http://localhost:3020/auth/health`
    3. Execute the smoke tests suite to ensure correct response format.
  </action>
  <acceptance_criteria>
    - Curl commands return HTTP 200 OK and valid JSON payloads.
  </acceptance_criteria>
</task>

## Success Criteria

1. **Clean Builds**: All Docker images compile and bundle cleanly using the monorepo source files.
2. **Cluster Health**: All container deployments are scheduled and become ready on Docker Desktop Kubernetes.
3. **External Verification**: Routing/Ingress operates successfully and validates service availability externally.
4. **Evidence Collection**: Complete operational logs and rollback steps are recorded in `INFRASTRUCTURE_CERTIFICATION.md`.
