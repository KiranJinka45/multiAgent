# Context: Phase 25.1 — Unified Institutional Command Dashboard

## Objective
Transform ZTAN from a technical substrate into a cognitively operable institutional system. Create a constitutionally truthful operational interface that compresses complexity into actionable cognition while preserving forensic depth and replayability.

## Requirements
- **Dashboard API Layer**:
    - `packages/dashboard-api/`: Backend services for aggregating institutional state, telemetry, and forensic history.
- **Dashboard Telemetry & Sociology Service**:
    - `packages/dashboard-telemetry/`: Module to compress multi-cell telemetry and sociological health metrics for the UI.
- **Dashboard Visualization Engine**:
    - `packages/dashboard-visualization/`: D3/Cytoscape-based engine for rendering governance timelines and federation topology.
- **Dashboard UI (Frontend)**:
    - `packages/dashboard-ui/`: Angular-based operational surface (simulated/mocked for initial delivery).
- **CLI (ztanctl dashboard)**:
    - New suite of commands: `dashboard serve`, `dashboard replay`, `dashboard sociology`, `dashboard archaeology`.

## Strategic Intent
Pivot from "Institutional Sociology" to **Civilizational Visibility**. ZTAN must be understandable to human operators, auditors, and executives. The dashboard acts as the cognitive bridge, ensuring that constitutional architecture is observable and manageable at scale without sacrificing cryptographic rigor.

## Success Criteria
- Institutional state is summarized into actionable views (Executive, Operator, Auditor).
- Governance timelines and federation topologies are visually explorable.
- Every UI claim is cryptographically traceable to replay evidence.
- Sociological degradation (fatigue, entropy) is empirically observable in the dashboard.
