<decisions>
## Implementation Decisions

### D-01: Mission Classification (T0–T5)
The system MUST enforce the following tier hierarchy:
- **T0 (Observational):** Read-only. 0% mutation. Max 60s runtime. Very low cost ceiling.
- **T1 (Sandbox-Constrained):** Sandbox-only mutation. Ephemeral persistence. Internal allowlist only. Max 3 min runtime.
- **T2 (Controlled Code Mutation):** **HITL Mandatory.** Single package root enforcement. Isolated branch mandatory. Max 5 min runtime.
- **T3 (Production-Affecting):** **Multi-party approval (2-of-3 quorum).** Shadow Rollback mandatory. Staged deployment.
- **T4 (Infrastructure):** **Emergency quorum (2/3).** Maintenance window only. Forensic archive mandatory.
- **T5 (Systemic/Cross-Tenant):** **PROHIBITED** during Phase 8.

### D-02: Automatic HITL Escalation Triggers (T1/T2)
Autonomy MUST fail upward to humans if any of the following occur:
- Patch > 50 LOC
- Security-sensitive dependency mutation
- Multiple package mutations detected (T2 single-root violation)
- Runtime instability or Retry loops > 2
- Cost > 80% of declared budget
- **Replay mismatch** or Policy ambiguity

### D-03: Boundary & Blast Radius Invariants
- **Network:** T1/T2 are restricted to **Internal-only allowlists**. No arbitrary internet, DNS resolution, or public HTTP browsing allowed.
- **Filesystem (T2):** Strict **Single Package Root** enforcement. Maximum directory depth escape = 0 (`../` traversal blocked).
- **Manifests:** All mutations MUST be pre-declared in a **Signed Blast Radius Manifest** (includes Package Root, File Globs, Max File Count, Max LOC Delta).
- **Enforcement:** **Post-execution hard enforcement** is mandatory. Any violation (unauthorized file creation, cross-package mutation) results in a mission kill and immediate rollback.

### D-04: Mission Lifecycle & Escalation
- **Irreversibility:** Missions may escalate upward (T1 → T2), but **NEVER de-escalate automatically**.
- **Mission Decay:** Automatic expiration of governance state (T0: Immediate, T1: 24h, T2: 7d, T3: 30d).
- **Shadow Rollback (T3):** Mandatory proof of revertibility in a twin environment before production execution.

</decisions>
