# Phase 12: Sentinel Resilience Drills — Plan 12.1

**Requirement:** `OPS-MAINT-SENTINEL-01`
**Objective:** Verify lease-fencing state recovery and step-down behavior under active Redis Sentinel quorum-loss simulations.
**Constraint:** NO NEW CORE ABSTRACTIONS

## Proposed Changes

### Sentinel Resilience Drill Script

#### [NEW] [redis-sentinel-drill.ts](file:///c:/multiagentic_project/multiAgent-main/scripts/redis-sentinel-drill.ts)
A standalone script that runs the Sentinel Quorum-Loss and Fencing Recovery drill.
- Baseline check: Verifies VFS advisory lock and Quota Engine succeed.
- Outage injection: Pauses Docker Redis/Sentinel containers or injects client proxy outage via `injectRedisOutage(15000)`.
- Fencing checks: Asserts VFS lock and tenant quota fail closed immediately during outage.
- Recovery checks: Clears outage and unpauses containers, waiting 5 seconds for connection re-stabilization, and verifies locks/quotas succeed.
- Telemetry output: Writes outcome JSON to `telemetry-history/redis_sentinel_latest.json`.

### package.json Registration

#### [MODIFY] [package.json](file:///c:/multiagentic_project/multiAgent-main/package.json)
Adds the command shortcut `"stewardship:sentinel:drill": "npx tsx scripts/redis-sentinel-drill.ts"`.

## Verification Plan

### Automated Verification
Run the drill via `pnpm` or `npx`:
```bash
npx tsx scripts/redis-sentinel-drill.ts
```
Expected output:
- Baseline locks/quota check succeed.
- Outage sets system into fail-closed mode.
- Locks throw/return null, quota check throws `QUOTA_UNAVAILABLE`.
- Healing restores connection.
- Locks/quota checks succeed post-outage.
- Output report written to `telemetry-history/redis_sentinel_latest.json`.
