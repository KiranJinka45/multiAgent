# Phase 11: Backup Corruption & Recovery Integrity — Plan 11.1

**Requirement:** `OPS-MAINT-BACKUP-01`
**Objective:** Verify graceful recovery pipeline failures and clear diagnostics under corrupted DB/queue backups.
**Constraint:** NO NEW CORE ABSTRACTIONS — all work in external `scripts/`.

## Deliverables

### 1. Backup Integrity Validator (`scripts/backup-integrity-validator.ts`)

A standalone pre-import validation gate that examines serialized backup dump files and produces structured diagnostics. Validates:

1. **Structural integrity** — Valid JSON, expected top-level keys (`blocks`, `walLogs`, `snapshots`), array types.
2. **Schema conformance** — Each record type has all required fields.
3. **Hash-chain continuity** — `blocks[i].prevHash === blocks[i-1].hash` for all i > 0.
4. **Epoch monotonicity** — Block epochs are non-decreasing.
5. **WAL sequence monotonicity** — WAL log `seq` values are strictly increasing with no duplicates.
6. **Truncation / null-padding detection** — File size > 0, no trailing null bytes, valid JSON parse.

### 2. Backup Corruption Drill (`scripts/backup-corruption-drill.ts`)

End-to-end drill that generates a synthetic clean baseline, systematically creates 7 corruption variants, validates each with the integrity validator, and produces a structured evidence report.

Corruption classes tested:
- `TRUNCATION` — file cut mid-stream
- `MALFORMED_JSON` — invalid JSON syntax
- `SCHEMA_VIOLATION` — required fields removed
- `HASH_CHAIN_BREAK` — prevHash values scrambled
- `EPOCH_REGRESSION` — block epochs going backwards
- `WAL_SEQUENCE_VIOLATION` — duplicate WAL seq values
- `NULL_PADDING` — trailing null bytes appended

### 3. Package Registration

- `stewardship:backup:validate` — Validate a backup file
- `stewardship:backup:drill` — Run the full corruption drill

## Acceptance Criteria

1. Clean backup passes validation (exit code 0).
2. All 7 corruption classes are detected by the validator.
3. The validator produces structured diagnostic output identifying the corruption class.
4. The drill produces a structured report at `evidence/backup-corruption-drill-report.json`.
5. No live database or Docker infrastructure required.
6. No new core abstractions or packages introduced.
